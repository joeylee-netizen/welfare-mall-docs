# /ux-review — UX 사전 리뷰

## 설명
Action/Wireframe 문서 작성 단계에서 UX 흐름을 사전 리뷰한다.
`/ux-audit`(발행 후 사후 감사)와 달리, 기획 문서 단계에서 사용성 문제를 조기 발견한다.

## 사용법
```
/ux-review BO-PDM-030              # 특정 Action 흐름 리뷰
/ux-review domains/BO/product      # 도메인 전체 흐름 리뷰
```

## /ux-audit 와의 차이

| 항목 | /ux-review | /ux-audit |
|------|-----------|-----------|
| 시점 | 기획 문서 작성 중 (사전) | HTML 발행 후 (사후) |
| 대상 | Action, Wireframe MD | HTML 와이어프레임 |
| 초점 | 사용자 흐름, 정보 구조 | 접근성(WCAG), 구현 품질 |

## 리뷰 항목

### 1. 사용자 흐름 분석

#### 태스크 완료 경로
- [ ] 주요 태스크(등록, 수정, 삭제)의 단계 수가 적절한지 (3~5단계 권장)
- [ ] 불필요한 중간 단계가 없는지
- [ ] 각 단계에서 사용자가 다음 행동을 알 수 있는지

#### 에러 복구
- [ ] 유효성 검사 실패 시 사용자가 어디를 수정해야 하는지 명확한지
- [ ] 에러 후 입력한 데이터가 유지되는지
- [ ] 되돌리기(undo) 또는 취소 경로가 있는지

#### 확인/경고
- [ ] 파괴적 액션(삭제, 취소)에 확인 단계가 있는지
- [ ] 확인 메시지가 구체적인지 ("정말 삭제하시겠습니까?" → "상품 'ABC'를 삭제하시겠습니까?")
- [ ] 되돌릴 수 없는 작업에 대한 경고가 있는지

### 2. 정보 구조

#### 화면 간 네비게이션
- [ ] 목록 → 상세 → 수정 흐름이 자연스러운지
- [ ] 뒤로가기/목록으로 돌아가기 경로가 명확한지
- [ ] 관련 화면 간 이동이 용이한지

#### 데이터 표시
- [ ] 목록 화면의 컬럼이 핵심 정보를 포함하는지
- [ ] 상세 화면에서 정보 그룹핑이 논리적인지
- [ ] 상태 표시가 직관적인지 (텍스트 + 색상)

### 3. BO 관리자 특화

#### 대량 작업
- [ ] 일괄 선택/해제 기능 설계 여부
- [ ] 선택 항목 수 표시 여부
- [ ] 일괄 작업 후 결과 피드백 설계 여부

#### 검색/필터
- [ ] 자주 사용하는 필터가 기본 노출되는지
- [ ] 필터 초기화 기능이 있는지
- [ ] 검색 결과 없음 상태 처리

#### 정렬
- [ ] 기본 정렬 기준이 명시되어 있는지
- [ ] 사용자 정렬 변경 가능 여부
- [ ] 정렬 방향(오름/내림) 표시

## 출력 형식

```
🔍 UX 사전 리뷰: BO-PDM-030 (상품 등록 액션)

사용자 흐름
  ✅ 등록 흐름: 3단계 (입력 → 확인 → 완료) — 적절
  ⚠️ 에러 복구: 유효성 실패 시 입력 데이터 유지 여부 미정의
  ✅ 삭제 확인: 확인 모달 설계됨

정보 구조
  ✅ 목록 → 상세 네비게이션 명확
  ⚠️ 상세 → 목록 복귀 경로 미정의

BO 특화
  ❌ 일괄 선택 후 결과 피드백 미설계
  ✅ 기본 정렬: 등록일 내림차순 명시

---
통과 N / 개선 권장 N / 미정의 N
```
