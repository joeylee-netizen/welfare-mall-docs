# 반품 상세 폼

## 개요

BO 관리자가 특정 반품 클레임의 전체 정보를 조회하고, 현재 상태에 따른 처리(승인·거절·수거요청·환불승인·검수거부·수기완료·재전송)를 수행하는 **모달형 상세 폼** 컴포넌트. [BO-CLM-023 반품 목록](./BO-CLM-023_반품-목록-테이블.md) 또는 [BO-CLM-020 통합 목록](./BO-CLM-020_배송상품-클레임-목록-테이블.md)에서 클레임코드 클릭 시 오버레이 형태로 열린다.

- 진입: `claim_id` 쿼리로 [BO-CLM-032 상세 조회](../04-actions/BO-CLM-032_주문취소-상세-조회.md) 액션 호출 (상세 조회는 claim_type 무관 공용).

---

## 모드 제어 (하단 버튼 분기)

| 조건 (claim_status_bo) | 좌측 | 우측 |
|------------------------|------|------|
| `RETURN_REQUESTED` | [닫기] | [거절] [승인] |
| `RETURN_RECEIVED` | [닫기] | [수거요청] |
| `RETURN_PICKUP_IN_PROGRESS` | [닫기] | (모니터링 — 버튼 없음) |
| `RETURN_PICKED_UP` | [닫기] | (모니터링) |
| `RETURN_COLLECTED` | [닫기] | [검수거부] [환불승인] |
| `REFUND_REQUESTED` | [닫기] | [환불 수기 완료] |
| `REFUND_FAILED` | [닫기] | [환불 수기 완료] [환불 재전송] |
| `REFUNDED` / `RETURN_WITHDRAWN` | [닫기] | (종결, 조회만) |

## 폼 구성 (6개 섹션)

### 섹션 1: 클레임 정보

| No | 필드명 | 데이터 필드 | 비고 |
|----|--------|------------|------|
| 1 | 클레임코드 | claim_code | `CLM...` |
| 2 | 클레임 유형 | claim_type | 반품 |
| 3 | 하위 유형 | claim_sub_type | 반품(사용자)/반품(대행) |
| 4 | FO 상태 | claim_status_fo | badge |
| 5 | BO 상태 | claim_status_bo | badge |
| 6 | 처리 채널 | process_channel | |
| 7 | 접수 채널 | applied_channel | |
| 8 | 신청자 | applied_by_name | |
| 9 | 신청일시 | applied_at | |
| 10 | 클레임 사유 | reason_code + reason_detail | |
| 11 | 귀책 | liability_party | badge |

### 섹션 2: 원주문 정보

- 주문번호(링크) · 주문일시 · 원주문 상태(배송완료) · 고객사
- 주문자(링크) · 연락처
- 판매사(링크) · 출고지
- 배송지 주소 full-width
- 결제수단 블록: PG 결제액 / 포인트 사용 / 사용 쿠폰 / 총 결제금액

### 섹션 3: 반품 대상 상품 (ClaimItem 목록)

| 컬럼 | 설명 |
|------|------|
| 상품명 | 링크 → 상품상세 팝업 |
| 옵션 | 색상/사이즈 등 |
| 수량 | 반품 대상 수량 |
| 단가 | 주문 시점 스냅샷 |
| 할인 분배 | 쿠폰/프로모션 분배액 |
| 환불 예정 | |
| 적용 쿠폰 | 미적용 시 "—" |

- 하단 합계 행: 수량 합계, 환불 예정 합계.

### 섹션 4: 수거·검수 정보

| No | 필드명 | 데이터 필드 | 입력 유형 | 비고 |
|----|--------|------------|-----------|------|
| 1 | 택배사 | pickup_carrier_name | text(읽기) | 수거요청 모달에서 등록 |
| 2 | 반송장 번호 | pickup_tracking_number | text(읽기) | |
| 3 | 수거 요청일 | pickup_requested_at | date | |
| 4 | 택배사 수령일 | pickup_picked_up_at | date | 시스템 자동 |
| 5 | 판매사 회수일 | pickup_returned_at | date | 시스템 자동 |
| 6 | 검수 결과 | inspection_result | badge | PASSED/FAILED_*/미검수 |
| 7 | 검수 메모 | inspection_memo | text(읽기) | |
| 8 | 검수자 | inspection_by_name | text | |
| 9 | 검수일시 | inspection_at | date | |

- 아직 해당 단계에 미도달인 필드는 "—" 표시.

### 섹션 5: 환불 상세

- 환불 요약 카드: 환불 총액 / PG 환불 / 포인트 복원 / 반품배송비
- 배송비 부담 주체 · 추가 배송비 · 쿠폰 원복 상태/메모
- 환불 수단 상세 테이블(RefundRecord): 수단/상태/금액/트리거/시도/PG 거래 ID/응답 메시지/요청·응답일시

### 섹션 6: 처리 이력 (타임라인)

- ClaimHistory 최신 순(DESC) 세로 타임라인.
- 각 이벤트: 시각 · 상태 전이 · 처리자/채널 · 메모.
- 수거 이벤트(반송장 등록/수령/회수) · 검수 이벤트 모두 포함.

## 상태 처리

| 상태 | 표시 |
|------|------|
| 로딩 | 섹션별 skeleton |
| 조회 실패 | "상세 정보를 불러올 수 없습니다." + 재시도 |
| 403 | 모달 닫힘 + 상위 알림 배너 |
| 404 | 모달 닫힘 + 토스트 |
| 처리 중 | 버튼 비활성 + 스피너 |
| 409 상태 충돌 | 토스트 + 자동 재조회 |
| 재시도 한도 초과 | 재전송 버튼 비활성 + 툴팁 |
