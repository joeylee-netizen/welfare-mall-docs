# 주문취소 상세 폼

## 개요

BO 관리자가 특정 주문취소 클레임의 전체 정보를 조회하고, 현재 상태에 따른 처리(승인·반려·환불완료·재전송)를 수행하는 **모달형 상세 폼** 컴포넌트이다. [BO-CLM-021 주문취소 목록](./BO-CLM-021_주문취소-목록-테이블.md) 또는 [BO-CLM-020 통합 목록](./BO-CLM-020_배송상품-클레임-목록-테이블.md)에서 클레임코드 클릭 시 오버레이 형태로 열린다. 화면 이동 없이 처리 후 자동으로 목록을 새로고침한다.

- 진입: `?claim_id={id}` 쿼리로 `[BO-CLM-032 상세 조회](../04-actions/BO-CLM-032_주문취소-상세-조회.md)` 액션 호출
- 모드: 단일 조회 모드(수정은 하단 버튼으로만 실행, 인라인 편집 없음)

---

## 모드 제어 (하단 버튼 분기)

하단 버튼 영역은 `claim_status_bo` × `approval_required`에 따라 동적으로 결정된다.

| 조건 | 표시 버튼 (좌측) | 표시 버튼 (우측) |
|------|------------------|------------------|
| `CANCEL_REQUESTED` + `approval_required = Yes` (상품준비중 건) | [닫기] | [반려] [승인] |
| `CANCEL_REQUESTED` + `approval_required = No` (결제완료 건, 시스템 자동처리 대기) | [닫기] | (버튼 없음) |
| `SALE_CANCEL_REQUESTED` | [닫기] | (버튼 없음, 모니터링만) |
| `REFUND_REQUESTED` | [닫기] | [환불 수기 완료] |
| `REFUND_FAILED` | [닫기] | [환불 수기 완료] [환불 재전송] |
| `REFUNDED` / `CANCEL_WITHDRAWN` | [닫기] | (종결 상태, 조회만) |

## 폼 구성 (5개 섹션)

### 섹션 1: 클레임 정보

| No | 필드명 | 데이터 필드 | 입력 유형 | 비고 |
|----|--------|------------|-----------|------|
| 1 | 클레임코드 | claim_code | text(읽기) | `CLM20260421000001` |
| 2 | 클레임 유형 | claim_type | text | 주문취소 |
| 3 | 하위 유형 | claim_sub_type | text | 주문취소(사용자)/판매취소(관리자) |
| 4 | FO 상태 | claim_status_fo | badge | |
| 5 | BO 상태 | claim_status_bo | badge | |
| 6 | 처리 채널 | process_channel | text | FO/BO_PROXY/SYSTEM |
| 7 | 접수 채널 | applied_channel | text | FO/BO_PROXY/ADMIN |
| 8 | 신청자 | applied_by_name | text | 구매자명 또는 관리자명 |
| 9 | 신청일시 | applied_at | date | YYYY.MM.DD HH:MM:SS |
| 10 | 클레임 사유 | reason_code + reason_detail | text(읽기) | 사유 라벨 + 상세 내용 |
| 11 | 귀책 구분 | liability_party | badge | 구매자/판매사 |
| 12 | 승인 필요 여부 | approval_required | text | Yes/No |

### 섹션 2: 원주문 정보

| No | 필드명 | 데이터 필드 | 입력 유형 | 비고 |
|----|--------|------------|-----------|------|
| 1 | 주문번호 | order_id | link | 주문상세 새 탭 열기 |
| 2 | 주문자 | buyer_name | link | 회원 상세 팝업 |
| 3 | 고객사 | client_name | text | 멀티태넌트 |
| 4 | 주문일시 | order_created_at | date | |
| 5 | 원주문 상태 | order_status | badge | 결제완료/상품준비중/배송중 등 |
| 6 | 출고지 | shipment_name | text | |
| 7 | 배송지 | shipping_address | text(읽기) | 배송지 주소 전체 |
| 8 | 판매사 | vendor_name | link | 판매사 정보 팝업 |
| 9 | 결제수단 | payment_method | text | 복지포인트 + 카드(BC/신한 등) |
| 10 | 결제금액 | payment_total | number | 원주문 총 결제금액 |
| 11 | PG 결제액 | payment_pg_amount | number | |
| 12 | 복지포인트 사용액 | payment_point_amount | number | |
| 13 | 원주문 쿠폰 사용 | used_coupon_list | list | 쿠폰명 + 할인금액 목록 |

### 섹션 3: 취소 대상 상품 (ClaimItem 목록)

| No | 컬럼명 | 데이터 필드 | 비고 |
|----|--------|------------|------|
| 1 | 상품명 | product_name | 링크: 상품상세 팝업 |
| 2 | 옵션 | option_name | 색상/사이즈 등 |
| 3 | 수량 | quantity | |
| 4 | 단가 | unit_price | 주문 시점 스냅샷 |
| 5 | 할인 분배 | discount_allocated | 쿠폰·프로모션 할당액 |
| 6 | 환불 예정 | item_refund_amount | |
| 7 | 적용 쿠폰 | coupon_name | 미적용 시 `-` |

- 목록 하단 합계 행: 수량 합계, 환불 예정 합계.

### 섹션 4: 환불 상세

| No | 필드명 | 데이터 필드 | 입력 유형 | 비고 |
|----|--------|------------|-----------|------|
| 1 | 환불 총액 | refund_total_amount | number | |
| 2 | PG 환불액 | refund_pg_amount | number | 카드/계좌이체 금액 |
| 3 | 복지포인트 복원액 | refund_point_amount | number | |
| 4 | 클레임 배송비 | shipping_fee_charged | number | 구매자 귀책 시 차감 |
| 5 | 배송비 부담 주체 | shipping_fee_liable_to | badge | 구매자/판매사 |
| 6 | 추가 배송비 | additional_shipping_fee | number | 무료배송 조건 미달 시 |
| 7 | 쿠폰 원복 상태 | coupon_restore_status | badge | 없음/원복필요/원복완료/수기발급필요 |
| 8 | 쿠폰 원복 메모 | coupon_restore_note | text(읽기) | CS 수기 발급 사유 등 |
| 9 | 환불 수단 상세 | RefundRecord 목록 | list | 수단별 trigger/상태/금액/시도 횟수 |

**환불 수단 상세 목록 컬럼:**

| 컬럼 | 설명 |
|------|------|
| 수단 | 카드(국내/해외) / 실시간 계좌이체 / 복지포인트 |
| 상태 | PENDING / SUCCESS / FAILED / MANUAL_COMPLETED |
| 금액 | 환불 요청 금액 |
| 트리거 | SYSTEM / BATCH / ADMIN_MANUAL |
| 시도 횟수 | retry_count |
| PG 거래 ID | pg_transaction_id |
| 응답 메시지 | pg_response_message (실패 시 빨간색) |
| 요청/응답 일시 | requested_at / responded_at |

### 섹션 5: 클레임 처리 이력 (타임라인)

`ClaimHistory` 전체를 **세로 타임라인**으로 표시.

| 요소 | 내용 |
|------|------|
| 시각 | `created_at` (YYYY.MM.DD HH:MM:SS) |
| 아이콘 색상 | 활성=`timeline_dot_active` / 완료=`done` / 실패=`failed` |
| 상태 전이 | `from_status` → `to_status` (라벨 형태) |
| 처리자 | `processor_name` (`process_channel` 뱃지 동시 표시) |
| 메모 | `memo` (반려사유·재전송 사유 등) |

- 기본 정렬: 최신 순(DESC).
- 신청 시 기록 이벤트(최초 생성)도 타임라인에 포함.

## 하단 버튼 동작

### 승인 버튼 (상품준비중 `CANCEL_REQUESTED`)

1. 확인 모달 열림: "본 건을 승인하시겠습니까? 승인 시 즉시 환불요청이 진행됩니다."
2. [승인] 클릭 → [BO-CLM-035](../04-actions/BO-CLM-035_주문취소-승인.md) 호출.
3. 성공: 토스트 "승인되었습니다." + 모달 내 상태 갱신 + 목록 자동 새로고침.

### 반려 버튼 (상품준비중 `CANCEL_REQUESTED`)

1. 반려 사유 입력 모달 열림(목록 테이블의 반려 모달과 동일 스펙, [BO-CLM-021 모달 (2)](./BO-CLM-021_주문취소-목록-테이블.md#모달-구성)).
2. [반려 확정] → [BO-CLM-036](../04-actions/BO-CLM-036_주문취소-반려.md) 호출.
3. 성공: 모달 내 상태를 `CANCEL_WITHDRAWN`으로 갱신 + 이력 섹션 자동 재조회.

### 환불 수기 완료 버튼 (`REFUND_REQUESTED` / `REFUND_FAILED`)

1. 확인 모달: "환불 수기 완료 처리 시 상태가 `환불완료`로 전환됩니다. 외부에서 환불 처리가 확인되셨습니까?"
2. 메모 입력(선택, 0~500자).
3. [완료 처리] → [BO-CLM-037](../04-actions/BO-CLM-037_환불-수기-완료.md) 호출.

### 환불 재전송 버튼 (`REFUND_FAILED`)

1. 확인 모달: "환불 요청을 재전송합니다. 당일 수동 재시도는 1회로 제한됩니다."
2. [재전송] → [BO-CLM-038](../04-actions/BO-CLM-038_환불-재전송.md) 호출.
3. 성공: 타임라인/환불 수단 상세에 신규 레코드 추가.

### 닫기 버튼

- 모달 닫힘. 호출측 목록은 변경 여부와 무관하게 새로고침(일괄 `refresh` 플래그).

## 인터랙션

| 액션 | 동작 |
|------|------|
| 주문번호 클릭 | 주문관리 모듈의 주문상세 새 탭 |
| 구매자 링크 클릭 | 회원 상세 팝업 |
| 판매사 링크 클릭 | 판매사 정보 팝업 |
| 상품명 클릭 | 상품상세 팝업(시점 스냅샷 안내 포함) |
| ESC 키 | 확인 없이 모달 닫기(단, 처리 모달이 열려 있는 경우는 그 모달만 닫음) |
| 배경 클릭 | 동작 없음(실수 방지) |
| 처리 모달 진행 중 | 외곽 모달 스크롤 잠금 |

## 상태 처리

| 상태 | 표시 |
|------|------|
| 로딩 | 섹션별 스켈레톤 |
| 조회 실패 | 모달 중앙에 "상세 정보를 불러올 수 없습니다." + 재시도 |
| 권한 부족(403) | 모달 즉시 닫힘 + 상위 알림 배너 |
| 처리 중(409 상태 충돌) | 토스트: "대상 건의 상태가 변경되었습니다. 새로고침합니다." + 상세 재조회 |
| 수기 완료/재전송 처리 중 | 버튼 비활성 + 스피너 |
| 수동 재시도 횟수 초과 | 재전송 버튼 비활성 + 툴팁: "금일 수동 재시도는 1회 제한입니다." |
