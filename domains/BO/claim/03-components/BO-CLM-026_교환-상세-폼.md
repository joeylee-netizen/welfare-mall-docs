# 교환 상세 폼

## 개요

BO 관리자가 특정 교환 클레임의 전체 정보를 조회하고, 상태별 처리(승인·거절·수거요청·최종승인·검수거부)를 수행하는 **모달형 상세 폼** 컴포넌트. [BO-CLM-025 교환 목록](./BO-CLM-025_교환-목록-테이블.md) 또는 [BO-CLM-020 통합 목록](./BO-CLM-020_배송상품-클레임-목록-테이블.md)에서 클레임코드 클릭 시 오버레이로 열린다. 반품 상세([BO-CLM-024](./BO-CLM-024_반품-상세-폼.md))와 유사하되 **교환 요청 옵션 섹션**과 **교환 최종승인 정보 섹션**이 추가된다.

- 진입: [BO-CLM-032 상세 조회](../04-actions/BO-CLM-032_주문취소-상세-조회.md) 공용 액션 호출.

---

## 모드 제어 (하단 버튼 분기)

| 조건 (claim_status_bo) | 좌측 | 우측 |
|------------------------|------|------|
| `EXCHANGE_REQUESTED` | [닫기] | [거절] [승인] |
| `EXCHANGE_RECEIVED` | [닫기] | [수거요청] |
| `EXCHANGE_PICKUP_IN_PROGRESS` | [닫기] | (모니터링) |
| `EXCHANGE_PICKED_UP` | [닫기] | (모니터링) |
| `EXCHANGE_COLLECTED` | [닫기] | [검수거부] [최종승인] |
| `EXCHANGE_FINAL_APPROVED` / `EXCHANGE_WITHDRAWN` | [닫기] | (종결, 조회만) |

> 교환은 환불 프로세스가 없으므로 환불 수기 완료·재전송 버튼이 존재하지 않는다.

## 폼 구성 (7개 섹션)

### 섹션 1: 클레임 정보

(반품 상세 섹션 1과 동일 구조) — 클레임코드·유형·하위유형·상태·채널·신청자·일시·사유·귀책.

### 섹션 2: 원주문 정보

- 주문번호·주문일시·원주문 상태(배송완료)·고객사
- 주문자·연락처·판매사·출고지·배송지
- 결제수단 블록: PG/포인트/쿠폰/총 결제금액

### 섹션 3: 교환 대상 상품 (원상품, ClaimItem 목록)

| 컬럼 | 설명 |
|------|------|
| 원상품명 | 링크 → 상품상세 팝업 |
| 원옵션 | 원주문 옵션 |
| 수량 | 교환 대상 수량 |
| 단가 | 주문 시점 스냅샷 |
| 할인 분배 | 쿠폰/프로모션 분배액 |
| 적용 쿠폰 | |

### 섹션 4: 교환 요청 옵션 (교환 전용 신규 섹션)

교환 대상 옵션 및 동일 상품·동일 가격 검증 결과를 표시.

| No | 필드명 | 데이터 필드 | 비고 |
|----|--------|------------|------|
| 1 | 교환 대상 상품 | exchange_target_product_id | 원상품과 동일해야 함 (검증 통과 표시) |
| 2 | 교환 대상 옵션 | exchange_target_option_name | 색상/사이즈 등 |
| 3 | 옵션 가격 | (조인) ProductOption.price | 원옵션 단가와 일치 검증 표시 |
| 4 | 선차감 재고 | exchange_inventory_reserved | Yes/No. Yes=신청 시 차감됨 |
| 5 | 재고 복원 필요 | (계산) | 종결 상태에 따라 Yes/No 표시 (철회·검수거부 시 Yes) |

- 섹션 배경 `exchange_target_highlight`(`#eff6ff`)로 시각 강조.
- 검증 통과/실패 배지: 동일 상품·동일 가격이면 ✅ PASS, 불일치면 ❌ FAIL(일반적으로 FAIL은 발생하지 않으나 데이터 이상 시 표시).

### 섹션 5: 수거·검수 정보

(반품 상세 섹션 4와 동일) — 택배사 / 반송장 / 수거 요청일 / 수령일 / 회수일 / 검수 결과 / 메모 / 검수자.

### 섹션 6: 교환 최종승인 정보 (교환 전용 신규 섹션)

교환 최종승인이 완료된 경우에만 데이터 표시, 그 외 "진행 중" 또는 "—" 표시.

| No | 필드명 | 데이터 필드 | 비고 |
|----|--------|------------|------|
| 1 | 최종승인 일시 | exchange_final_approved_at | |
| 2 | 최종승인자 | (조인) | ClaimHistory 최종승인 이벤트 처리자 |
| 3 | 교환주문번호 | exchange_order_id | link → 주문관리 모듈 주문상세 |
| 4 | 교환주문 발급 상태 | (주문 모듈 조회) | 발급완료/발급실패 |
| 5 | 재배송 송장 | exchange_redelivery_tracking | 주문 모듈에서 동기화. 미발송 시 "—" |
| 6 | 재배송 상태 | (주문 모듈 조회) | 배송준비/배송중/배송완료 |

- 교환주문번호 클릭 → 주문관리 모듈 주문상세 새 탭(교환주문 정보 확인 가능).

### 섹션 7: 처리 이력 (타임라인)

- ClaimHistory 최신 순(DESC) 세로 타임라인.
- 재고 선차감/복원 이벤트, 수거 이벤트, 검수 이벤트, 교환주문 발급 이벤트 모두 포함.

## 상태 처리

| 상태 | 표시 |
|------|------|
| 로딩 | 섹션별 skeleton |
| 조회 실패 | 재시도 |
| 403 / 404 | 모달 닫힘 + 상위 알림 |
| 처리 중 | 버튼 비활성 + 스피너 |
| 409 상태 충돌 | 자동 재조회 |
| **재고 선차감 부족(접수 시)** | 토스트: "교환 대상 재고가 부족합니다." + 신청 거부 |
| **교환주문 발급 실패** | 토스트 + 재시도 버튼 활성 |
| **재고 복원 실패(거절/검수거부 시)** | 토스트 + 이력 기록 + CS 알림 |
