메뉴 경로: (모달) 주문취소 목록에서 행 클릭

Route: /bo/claim/delivery/cancel/:claim_id

1 상세 모달 헤더
  • 타이틀: 주문취소 상세 [클레임코드]
  • [X] 닫기 버튼 — ESC 키로도 닫힘 (단, 처리 모달 열려 있으면 그 모달만 닫힘)
  • 배경 클릭: 무시 (실수 방지)
  • 모달 너비 1200px, 최대 높이 90vh, 내부 스크롤
오픈 시 API 호출: GET /api/v1/claims/{claim_id} (BO-CLM-032)
2 섹션 1: 클레임 정보
  • 2열 key-value 레이아웃 (12개 필드)
  • 클레임코드 · 유형 · 하위 유형 · 승인 필요 · FO/BO 상태 · 처리/접수 채널 · 신청자 · 사유 · 귀책
  • 사유 상세: full-width (풀 폭 1개 행)
3 섹션 2: 원주문 정보
  • 주문번호(링크 → 주문상세 새 탭), 주문자(회원 상세 팝업), 판매사(정보 팝업) 링크 처리
  • 배송지 주소 full-width
  • 하단 결제수단 블록: PG/포인트 분리 + 사용 쿠폰 + 총 결제금액
4 섹션 3: 취소 대상 상품
#컬럼명비고
1상품명링크 → 상품상세 팝업(시점 스냅샷)
2옵션색상/사이즈 등
3수량대상 수량
4단가주문 시점 스냅샷
5할인 분배쿠폰·프로모션 분배액
6환불 예정단가×수량 - 할인
7적용 쿠폰미적용 시 "—"
하단에 합계 행(수량/환불 합계) 고정 표시
5 섹션 4: 환불 상세
  • 상단 요약 카드 4개: 환불 총액 / PG 환불 / 포인트 복원 / 클레임 배송비
  • 부대 정보: 배송비 부담 주체, 추가 배송비, 쿠폰 원복 상태/메모
  • 환불 수단 상세 테이블(RefundRecord): 수단/상태/금액/트리거/시도횟수/PG 거래 ID/응답 메시지/요청·응답일시
쿠폰 원복 상태: NONE/REQUIRED/COMPLETED/MANUAL_REQUIRED — MANUAL_REQUIRED는 쿠폰 종료일 경과로 CS 수동 재발급 필요
6 섹션 5: 클레임 처리 이력 (타임라인)
  • 세로 타임라인 (최신 순 DESC)
  • 아이콘 색: 진행 중=파랑, 완료=초록, 실패=빨강
  • 각 이벤트: 시각 · 상태 전이 · 처리자/채널 · 메모
ClaimHistory 엔티티 원본 모두 표시 (최초 신청 포함)

승인 처리 프로세스
  • [승인] 클릭 → 확인 모달: "본 건을 승인하시겠습니까? 승인 시 즉시 환불요청이 진행됩니다."
  • 확인 → API 호출 → 토스트 "승인되었습니다." → 상세 재조회 + 목록 새로고침
API: PATCH /api/v1/claims/{claim_id}/approve (BO-CLM-035)
상태: CANCEL_REQUESTED → REFUND_REQUESTED
반려 처리 프로세스
  • [반려] 클릭 → 반려사유 입력 모달(10~200자 필수) + FO 안내 템플릿 선택
  • 확인 → API 호출 → 상태 CANCEL_WITHDRAWN으로 전환 + 원주문 상태 복원 + FO 알림톡 발송
API: PATCH /api/v1/claims/{claim_id}/reject (BO-CLM-036)
환불 수기 완료 프로세스
  • [환불 수기 완료] 클릭 → 확인 모달(메모 입력 선택)
  • 외부(PG사 콘솔 등)에서 환불을 직접 처리한 경우 상태를 REFUNDED로 확정
API: PATCH /api/v1/claims/{claim_id}/refund/complete (BO-CLM-037)
RefundRecord에 MANUAL_COMPLETED 레코드 기록
환불 재전송 프로세스
  • [환불 재전송] 클릭 → 확인 모달 → API 호출
  • 당일 수동 재시도 1회 제한 (초과 시 409 DAILY_RETRY_LIMIT_EXCEEDED)
API: POST /api/v1/claims/{claim_id}/refund/retry (BO-CLM-038)
상태: REFUND_FAILED → REFUND_REQUESTED (재시도)
