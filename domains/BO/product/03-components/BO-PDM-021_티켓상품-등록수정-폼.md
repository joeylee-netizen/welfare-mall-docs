# 티켓상품 등록/수정 폼

## 개요

BO 관리자가 티켓형 상품(일반 티켓 상품, 예약 티켓 상품)을 **신규 등록**하거나 **기존 상품을 수정**하는 듀얼모드 폼 컴포넌트이다. [BO-PDM-001](../01-policies/BO-PDM-001_상품-관리-정책.md)의 메뉴 구조 중 **상품 관리 > 상품 등록/수정 > 티켓상품 등록/수정**에 해당한다.

- **등록 모드:** 메뉴 직접 진입 시 (product_id 없음), 빈 폼으로 신규 상품 입력
- **수정 모드:** 티켓상품 목록([BO-PDM-025](./BO-PDM-025_티켓상품-목록-테이블.md))에서 행 클릭 시 (product_id 있음), 기존 데이터 로드

---

## 모드 제어

[BO-PDM-001](../01-policies/BO-PDM-001_상품-관리-정책.md)의 등록/수정 폼 모드 제어 정책에 따른다.

| 조건 | 모드 | 편집 범위 | 헤더 타이틀 |
|------|------|----------|------------|
| product_id 없음 (메뉴 직접 진입) | 등록 모드 | 모든 필드 입력 가능 | 티켓상품 등록 |
| product_id 있음 + REGISTERING | 수정 모드 | 전체 편집 가능 | 티켓상품 수정 |
| product_id 있음 + PENDING | 조회 모드 | 읽기전용 | 티켓상품 상세 (승인대기) |
| product_id 있음 + APPROVED | 수정 모드 | 상품명, 판매상태, 판매기간 편집 | 티켓상품 수정 |
| product_id 있음 + REJECTED | 수정 모드 | 전체 편집 가능 | 티켓상품 수정 (반려) |

## 폼 구성

### 섹션 1: 기본정보

| No | 필드명 | 데이터 필드 | 입력 유형 | 등록 모드 | 수정(REGISTERING/REJECTED) | 수정(APPROVED) | 조회(PENDING) | 필수 | 비고 |
|----|--------|------------|-----------|-----------|--------------------------|---------------|--------------|------|------|
| 1 | 상품코드 | product_code | Text | 미표시 | 읽기전용 | 읽기전용 | 읽기전용 | - | 승인완료 시 자동 부여 |
| 2 | 요청코드 | request_code | Text | 미표시 | 읽기전용 | 읽기전용 | 읽기전용 | - | 저장 시 자동 발번 |
| 3 | 상품유형 | product_type | Select | 편집가능 | 편집가능 | 읽기전용 | 읽기전용 | Y | TICKET_COUPON, TICKET_RESERVATION |
| 4 | 상품명 | product_name | Text | 편집가능 | 편집가능 | 편집가능 | 읽기전용 | Y | 최대 200자 |
| 5 | 판매사 | vendor_id | Select (자동완성) | 편집가능 | 편집가능 | 읽기전용 | 읽기전용 | Y | 판매사 검색/선택 |

- `product_type` 옵션: **일반 티켓 상품**(TICKET_COUPON), **예약 티켓 상품**(TICKET_RESERVATION)
- `vendor_id`는 티켓형 상품의 귀속 주체로 필수이다.

### 섹션 2: 티켓 정보

| No | 필드명 | 데이터 필드 | 입력 유형 | 등록 모드 | 수정(REGISTERING/REJECTED) | 수정(APPROVED) | 조회(PENDING) | 필수 | 비고 |
|----|--------|------------|-----------|-----------|--------------------------|---------------|--------------|------|------|
| 1 | 유효기간 | validity_period | DateRange | 편집가능 | 편집가능 | 읽기전용 | 읽기전용 | Y | 티켓 사용 가능 기간 |
| 2 | 이용 안내 | usage_info | Textarea | 편집가능 | 편집가능 | 읽기전용 | 읽기전용 | Y | 이용 장소, 이용 방법 등 |
| 3 | 발급 수단 | issue_method | Select | 편집가능 | 편집가능 | 읽기전용 | 읽기전용 | Y | MMS, 알림톡, 앱푸시 등 |
| 4 | 예약 정보 | reservation_info | Textarea | 편집가능 | 편집가능 | 읽기전용 | 읽기전용 | C | 예약 안내, 예약 가능 일시 등 |

- `예약 정보`는 상품유형이 **예약 티켓 상품**(TICKET_RESERVATION)일 때만 표시되며 필수 입력이다.
- `발급 수단` 옵션: MMS, 알림톡, 앱푸시

### 섹션 3: 상태정보

| No | 필드명 | 데이터 필드 | 입력 유형 | 등록 모드 | 수정(REGISTERING/REJECTED) | 수정(APPROVED) | 조회(PENDING) | 필수 | 비고 |
|----|--------|------------|-----------|-----------|--------------------------|---------------|--------------|------|------|
| 1 | 승인상태 | approval_status | Badge | 미표시 | 읽기전용 | 읽기전용 | 읽기전용 | - | 상태별 색상 badge |
| 2 | 판매상태 | sales_status | Select | 미표시 | 미표시 | 편집가능 | 읽기전용 | - | APPROVED일 때만 편집 가능 |
| 3 | 판매시작일 | sales_start_date | DatePicker | 미표시 | 미표시 | 편집가능 | 읽기전용 | - | APPROVED일 때만 편집 가능 |
| 4 | 판매종료일 | sales_end_date | DatePicker | 미표시 | 미표시 | 편집가능 | 읽기전용 | - | 시작일 이후만 선택 가능 |

- 등록 모드 / REGISTERING / REJECTED 상태에서는 판매 관련 필드가 표시되지 않는다.
- APPROVED 상태에서의 판매상태 변경 규칙은 [BO-PDM-001](../01-policies/BO-PDM-001_상품-관리-정책.md) 참조.

#### 판매상태 변경 규칙

| 현재 상태 | 변경 가능 상태 |
|-----------|---------------|
| 판매중 | 판매일시중지, 판매종료 |
| 판매일시중지 | 판매중 |
| 일시품절 | 판매중 |
| 품절 | 판매중 |

### 섹션 4: 승인 이력 (수정/조회 모드만)

[BO-PDM-010](../02-data/BO-PDM-010_상품-엔티티.md)의 ProductApprovalHistory 엔티티 기반.

| No | 컬럼명 | 데이터 필드 | 타입 | 비고 |
|----|--------|------------|------|------|
| 1 | No | - | number | 행 번호 |
| 2 | 행위 | action | text | ApprovalAction Enum label |
| 3 | 이전 상태 | previous_status | badge | 승인상태 badge |
| 4 | 변경 상태 | new_status | badge | 승인상태 badge |
| 5 | 반려사유 | rejection_reason | text | REJECT 시에만 표시 |
| 6 | 변경자 | changed_by | text | |
| 7 | 변경일시 | changed_at | datetime | `YYYY-MM-DD HH:mm` |

- 최신순 정렬 (변경일시 desc)
- 등록 모드에서는 미표시

## 하단 버튼 구성

| 모드 | 좌측 | 우측 |
|------|------|------|
| 등록 모드 | - | `저장` (Primary) |
| 수정 (REGISTERING) | `삭제` (Danger) | `저장`, `승인요청` (Primary) |
| 수정 (REJECTED) | - | `저장`, `재승인요청` (Primary) |
| 수정 (APPROVED) | - | `저장` (Primary) |
| 조회 (PENDING) | - | `승인철회` |

## 인터랙션

### 등록 모드 — 저장

1. 모든 필수 필드 입력 후 `저장` 버튼 클릭
2. 클라이언트 검증 수행:
   - 상품유형: 미선택 불가
   - 상품명: 빈 값 불가, 200자 이내
   - 판매사: 미선택 불가
   - 유효기간: 시작일·종료일 모두 필수, 종료일이 시작일 이후
   - 이용 안내: 빈 값 불가
   - 발급 수단: 미선택 불가
   - 예약 정보: 상품유형이 TICKET_RESERVATION일 때 빈 값 불가
3. 검증 통과 시 확인 모달: "티켓상품을 등록하시겠습니까?"
4. 확인 시 API 호출 → approval_status: REGISTERING, request_code 자동 발번
5. 저장 완료 후 수정 모드로 전환 (product_id 부여) + 성공 토스트

### 수정 모드 — 저장

1. 수정 후 `저장` 버튼 클릭
2. 클라이언트 검증 수행 (등록 모드와 동일)
3. APPROVED 상태: 확인 모달 "수정 사항을 저장하시겠습니까? 즉시 FO에 반영됩니다."
4. 그 외 상태: 확인 모달 "수정 사항을 저장하시겠습니까?"
5. 확인 시 API 호출하여 저장
6. 저장 완료 시 성공 토스트 표시 + 데이터 갱신

### 승인요청

1. REGISTERING 상태에서 `승인요청` 버튼 클릭
2. 확인 모달: "상품 승인을 요청하시겠습니까? 승인대기 상태에서는 수정할 수 없습니다."
3. 확인 시 API 호출 → approval_status: PENDING
4. 처리 완료 후 조회 모드(PENDING)로 전환 + 성공 토스트

### 재승인요청

1. REJECTED 상태에서 `재승인요청` 버튼 클릭
2. 확인 모달: "수정된 상품의 승인을 재요청하시겠습니까?"
3. 확인 시 API 호출 → approval_status: PENDING
4. 처리 완료 후 조회 모드(PENDING)로 전환 + 성공 토스트

### 승인철회

1. PENDING 상태에서 `승인철회` 버튼 클릭
2. 확인 모달: "승인요청을 철회하시겠습니까? 철회 후 수정 및 삭제가 가능합니다."
3. 확인 시 API 호출 → approval_status: WITHDRAWN
4. 처리 완료 후 수정 모드로 전환 + 성공 토스트

### 삭제

1. REGISTERING 상태에서 `삭제` 버튼 클릭
2. 확인 모달: "이 상품을 삭제하시겠습니까? 삭제된 상품은 복구할 수 없습니다." (Danger)
3. 확인 시 API 호출하여 삭제
4. 삭제 완료 후 티켓상품 목록([BO-PDM-025](./BO-PDM-025_티켓상품-목록-테이블.md))으로 이동 + 성공 토스트

### 목록으로 돌아가기

1. `목록으로` 버튼 클릭 (수정/조회 모드에서만 표시)
2. 변경사항이 있는 경우: "저장하지 않은 변경 사항이 있습니다. 이동하시겠습니까?" 확인 모달
3. 확인 시 티켓상품 목록([BO-PDM-025](./BO-PDM-025_티켓상품-목록-테이블.md))으로 이동
4. 이전 검색 조건 유지

### 상품유형 변경 시 (등록/REGISTERING/REJECTED)

1. 상품유형 Select 변경
2. TICKET_RESERVATION 선택 시: 예약 정보 필드 표시
3. TICKET_COUPON 선택 시: 예약 정보 필드 숨김 + 입력값 초기화

## 상태 처리

| 상태 | 설명 | UI 표현 |
|------|------|---------|
| 등록 초기 | 메뉴 직접 진입 (빈 폼) | 모든 필드 편집 가능, 저장 버튼 표시 |
