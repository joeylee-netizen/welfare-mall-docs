# 티켓상품 승인 목록 테이블

## 개요

BO 관리자가 티켓형 상품의 승인대기 목록을 조회하고, 승인 또는 반려 처리하는 목록 컴포넌트이다. [BO-PDM-001](../01-policies/BO-PDM-001_상품-관리-정책.md)의 메뉴 구조 중 **상품 관리 > 상품 승인 관리 > 티켓상품 승인 목록**에 해당한다. 승인 시 상품코드가 자동 부여되며, 반려 시 반려사유 입력이 필수이다.

- 조회 대상: product_category = `TICKET` (티켓형) 상품만 표시
- product_type 범위: `TICKET_COUPON`, `TICKET_RESERVATION`

---

## 검색 필터 구성

| No | 필터명 | 데이터 필드 | 입력 유형 | 기본값 | 비고 |
|----|--------|------------|-----------|--------|------|
| 1 | 승인상태 | approval_status | Select | PENDING (승인대기) | ApprovalStatus Enum 옵션 |
| 2 | 상품유형 | product_type | Select | 전체 | TICKET_COUPON, TICKET_RESERVATION만 표시 |
| 3 | 상품명 | product_name | Text | - | 부분 일치(LIKE) 검색 |
| 4 | 요청기간 | created_at | DateRange | 최근 1개월 | 승인요청 접수 기간 |

- 기본 진입 시 승인상태가 `승인대기`로 설정되어 조회된다.
- `검색` 버튼 클릭 또는 Enter 키로 조회를 실행한다.
- `초기화` 버튼 클릭 시 모든 필터를 기본값으로 되돌린다.

## 컬럼 구성

| No | 컬럼명 | 데이터 필드 | 타입 | 정렬 | 비고 |
|----|--------|------------|------|------|------|
| 1 | 체크박스 | - | checkbox | - | 일괄 처리용 행 선택 |
| 2 | No | - | number | - | 행 번호 (페이지 기준 자동 채번) |
| 3 | 요청코드 | request_code | text | - | |
| 4 | 상품명 | product_name | text | - | |
| 5 | 상품유형 | product_type | text | - | Enum label 표시 |
| 6 | 판매사 | vendor_id | text | - | 판매사명 표시 |
| 7 | 승인상태 | approval_status | badge | - | 상태별 색상 badge |
| 8 | 요청일 | created_at | date | desc | `YYYY-MM-DD` 형식, 기본 정렬 |
| 9 | 요청자 | changed_by | text | - | 승인요청(REQUEST) 행위의 변경자 |

- 헤더의 전체 선택 체크박스로 현재 페이지 전체 선택/해제 가능
- 체크박스 선택은 `PENDING`(승인대기) 상태 행에서만 활성화

## 상태 badge 정의

| 값 | 라벨 | 색상 |
|----|------|------|
| REGISTERING | 상품등록중 | gray |
| PENDING | 승인대기 | blue |
| WITHDRAWN | 승인철회 | orange |
| APPROVED | 승인완료 | green |
| REJECTED | 승인반려 | red |

## 승인/반려 모달

### 승인 확인 모달

| 항목 | 내용 |
|------|------|
| 트리거 | 개별 행의 승인 버튼 또는 일괄 승인 버튼 클릭 |
| 제목 | 티켓상품 승인 확인 |
| 본문 | "선택한 N건의 티켓상품을 승인하시겠습니까? 승인 시 상품코드가 부여됩니다." |
| 버튼 | `취소`, `승인` (Primary) |
| 처리 | 승인 클릭 시 API 호출 → approval_status를 APPROVED로 변경 + product_code 자동 부여 |

### 반려 사유 입력 모달

| 항목 | 내용 |
|------|------|
| 트리거 | 개별 행의 반려 버튼 클릭 |
| 제목 | 티켓상품 승인 반려 |
| 본문 | 반려 대상 상품 정보 (요청코드, 상품명, 판매사) 표시 |
| 입력 | 반려사유 Textarea (필수, 최대 500자) |
| 버튼 | `취소`, `반려` (Danger) |
| 검증 | 반려사유 미입력 시 "반려사유를 입력해 주세요." 인라인 오류 |
| 처리 | 반려 클릭 시 API 호출 → approval_status를 REJECTED로 변경 + 이력 기록 |

## 인터랙션

### 검색

1. 필터 조건 입력 후 `검색` 버튼 클릭 또는 Enter 키 입력
2. 입력된 조건 + product_category=TICKET 필터로 API 호출
3. 결과를 테이블에 표시하고 검색결과 건수를 갱신
4. 체크박스 선택 상태 초기화

### 행 선택 (체크박스)

1. 개별 행의 체크박스 클릭 시 해당 행 선택/해제
2. 헤더 전체 선택 체크박스 클릭 시 현재 페이지 전체 선택/해제
3. `PENDING` 상태가 아닌 행의 체크박스는 비활성화
4. 1건 이상 선택 시 `일괄 승인` 버튼 활성화

### 일괄 승인

1. 체크박스로 승인 대상 행 선택 (1건 이상)
2. `일괄 승인` 버튼 클릭
3. 승인 확인 모달 표시 (선택 건수 포함)
4. `승인` 버튼 클릭 시 선택된 전체 상품 일괄 승인 API 호출
5. 처리 완료 후 목록 재조회 + 성공 토스트 표시

### 개별 승인

1. 테이블 행 우측의 `승인` 버튼 클릭
2. 승인 확인 모달 표시 (1건)
3. `승인` 버튼 클릭 시 API 호출
4. 처리 완료 후 해당 행의 승인상태 갱신 + 성공 토스트 표시

### 개별 반려

1. 테이블 행 우측의 `반려` 버튼 클릭
2. 반려 사유 입력 모달 표시
3. 반려사유 입력 후 `반려` 버튼 클릭
4. 반려사유 미입력 시 인라인 오류 메시지 표시
5. 검증 통과 시 API 호출
6. 처리 완료 후 해당 행의 승인상태 갱신 + 성공 토스트 표시

## 상태 처리

| 상태 | 설명 | UI 표현 |
|------|------|---------|
| 초기 | 페이지 최초 진입 | 승인상태 기본값 `승인대기`로 자동 검색 |
| 로딩 | API 호출 중 | 테이블 영역에 로딩 스피너 표시, 버튼 비활성화 |
| 데이터 없음 | 조회 결과 0건 | 테이블 영역에 "승인 대기 중인 티켓상품이 없습니다." 메시지 표시 |
| 조회 완료 | 데이터 정상 반환 | 테이블에 데이터 표시, PENDING 행만 체크박스 활성화 |
| 승인 처리 중 | 승인 API 호출 중 | 모달의 승인 버튼 로딩 상태, 닫기 불가 |
| 반려 처리 중 | 반려 API 호출 중 | 모달의 반려 버튼 로딩 상태, 닫기 불가 |
| 처리 완료 | 승인/반려 성공 | 모달 닫힘, 목록 재조회, 성공 토스트 표시 |
| 오류 | API 호출 실패 | 토스트 알림으로 오류 메시지 표시, 모달 유지 (재시도 가능) |
