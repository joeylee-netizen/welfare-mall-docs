# 할인프로모션 정책

## 목적

BO 관리자가 복지몰 상품에 대한 할인프로모션을 등록·운영·관리할 때 따라야 할 기준과 절차를 정의한다. 프로모션 구분, 할인 방식, 중복 규칙, 쿠폰 연계, 가격 산출 체계의 일관성을 확보하여 FO 서비스의 가격 정합성을 보장한다.

---

## 1. 프로모션 구분

프로모션은 할인 비용 부담 주체에 따라 3종으로 구분한다.

| 구분 | 코드 | 설명 | 할인 비용 부담 |
|------|------|------|---------------|
| **메가존 할인 (판매사 부담)** | MZ_VENDOR | 메가존 주도 프로모션, 할인 비용은 판매사가 100% 부담 | 판매사 100% |
| **메가존 할인 (복지몰 부담)** | MZ_PLATFORM | 메가존 주도 프로모션, 할인 비용은 복지몰이 100% 부담 | 복지몰 100% |
| **판매사 할인** | VENDOR | 판매사가 자체적으로 진행하는 할인 프로모션 | 판매사 100% |

---

## 2. 대상 및 회원

### (1) 대상 상품

- 프로모션 대상은 **특정 상품코드를 직접 선택**하여 지정한다.
- 대상 상품은 반드시 **승인완료(APPROVED)** 상태여야 한다.
- 하나의 프로모션에 **복수 상품**을 지정할 수 있다.
- 상품 유형 제한 없음 (배송형, 티켓형 모두 가능).

### (2) 대상 회원

- **전체 회원** 대상으로 적용한다.
- 특정 회원 그룹 제한은 1차 범위에 포함하지 않는다.

---

## 3. 할인 옵션

### (1) 할인 방식

- **즉시할인** 방식만 지원한다.
- 할인금액은 **원(KRW) 단위로 직접 입력**한다.
- 할인율(%) 방식은 1차 범위에서 제외한다.

### (2) 할인 기간

- 프로모션 **시작일시**와 **종료일시**를 설정한다.
- 종료일시는 시작일시보다 미래 시점이어야 한다.
- 기간 내 자동 적용, 기간 종료 시 자동 해제된다.

### (3) 중복 규칙

- **동일 상품**에 대해 **동일 기간 내 중복 프로모션 등록 불가**.
- 기간이 중복되지 않으면 **복수 프로모션 등록 가능**.
- 중복 검증은 프로모션 등록/수정 시 시스템에서 자동 수행한다.

### (4) 쿠폰 적용 규칙

| No | 규칙 | 설명 |
|----|------|------|
| 1 | 쿠폰 적용 가능/불가 설정 | 프로모션별로 쿠폰 중첩 허용 여부를 설정한다 |
| 2 | 적용 순서 | (1차) 즉시할인 → (2차) 쿠폰 할인 순서로 적용한다 |
| 3 | 쿠폰 적용 불가 시 | 즉시할인가가 최종 판매가가 된다 |
| 4 | 쿠폰 적용 가능 시 | 즉시할인가에서 쿠폰 할인을 추가 적용한다 |

---

## 4. 적용 순서 및 중복 처리

### (1) 동일 기간 중복 불가

- 동일 상품에 대해 기간이 겹치는 프로모션은 등록할 수 없다.
- 등록/수정 시 시스템이 자동으로 기간 중복을 검증한다.
- 중복 발견 시 오류 메시지와 함께 등록이 거부된다.

### (2) 기간 비중복 복수 등록

- 기간이 겹치지 않는 경우 동일 상품에 복수 프로모션을 등록할 수 있다.
- 예: 4/1~4/15 프로모션A, 4/16~4/30 프로모션B → 허용

### (3) 중지 후 재등록

- 진행중(ACTIVE) 프로모션을 중지(PAUSED)한 후, 해당 기간에 새로운 프로모션 등록이 가능하다.
- 중지된 프로모션의 남은 기간은 더 이상 점유하지 않는다.

---

## 5. 가격 산출 체계

| 단계 | 가격 | 산출 방식 | 비고 |
|------|------|----------|------|
| 1 | **판매가** | 상품 등록 시 설정된 가격 | 기준가 |
| 2 | **즉시할인가** | 판매가 - 할인금액 | 프로모션 기간 내 자동 적용 |
| 3 | **쿠폰할인가** | 즉시할인가 - 쿠폰할인금액 | 쿠폰 적용 가능 시에만 |

**산출 예시:**

```
판매가: 50,000원
할인금액: 5,000원
→ 즉시할인가: 45,000원
→ 쿠폰할인가: 45,000원 - 3,000원(쿠폰) = 42,000원
```

**제약 조건:**
- 할인금액은 판매가를 초과할 수 없다.
- 즉시할인가는 0원 이상이어야 한다.

---

## 6. 등록 플로우

프로모션 등록 시 다음 순서로 처리한다.

```
[BO] 프로모션 정보 입력
  → 저장 버튼 클릭
  → (1) 대상 상품 승인완료 여부 체크
    → 미승인 상품 존재 시 → 오류 (등록 불가)
  → (2) 기간 중복 체크
    → 동일 상품 동일 기간 프로모션 존재 시 → 오류 (등록 불가)
  → (3) 프로모션코드 자동 발급
  → (4) DB 저장 (status: ACTIVE)
  → 등록 완료
```

---

## 7. FO 전시 규칙

| 조건 | FO 적용 | FO 전시 | 설명 |
|------|:-------:|:-------:|------|
| 프로모션 기간 내 + ACTIVE | O | O | 즉시할인가 자동 적용 및 전시 |
| 프로모션 기간 외 | X | X | 할인 미적용, 원래 판매가 전시 |
| 프로모션 PAUSED | X | X | 즉시 할인 해제 |
| 프로모션 ENDED | X | X | 할인 미적용 |

- 프로모션 기간 내에는 FO 상품 상세에 **할인 정보(할인금액, 할인율)가 자동 전시**된다.
- 기간 종료 시 시스템이 자동으로 할인을 해제하고 원래 판매가로 복원한다.

---

## 8. 상태 전이

프로모션의 상태는 다음과 같이 관리한다.

| 상태 | 코드 | 설명 |
|------|------|------|
| **임시저장** | DRAFT | 등록 정보 임시 저장 상태 |
| **진행중** | ACTIVE | 프로모션 기간 내 적용 중 |
| **중지** | PAUSED | 관리자가 수동 중지 |
| **종료** | ENDED | 프로모션 기간 만료 |
| **삭제** | DELETED | 소프트 삭제 |

**상태 전환 규칙:**

```
DRAFT → ACTIVE : 등록 완료 (기간 도래 시)
ACTIVE → PAUSED : 관리자 수동 중지
ACTIVE → ENDED  : 기간 만료 시 시스템 자동 전환
PAUSED → ACTIVE : 관리자 재활성화 (기간 내)
PAUSED → DELETED : 관리자 삭제
DRAFT → DELETED  : 관리자 삭제
ENDED → DELETED  : 관리자 삭제
```

---

## 9. 수정 규칙

| 상태 | 수정 가능 여부 | 수정 범위 |
|------|:-----------:|----------|
| DRAFT | O | 전체 필드 수정 가능 |
| ACTIVE | △ | 종료일시, 쿠폰적용여부만 수정 가능 |
| PAUSED | X | 수정 불가 (삭제 후 재등록) |
| ENDED | X | 수정 불가 |

---

## 적용 범위

- **대상 시스템:** BO 관리자 시스템
- **대상 사용자:** BO 관리자
- **전제 조건:**
  - BO 관리자 권한 보유
  - 대상 상품이 승인완료(APPROVED) 상태
- **예외 사항:** 시스템 점검 시 프로모션 등록/수정 일시 중단 가능
