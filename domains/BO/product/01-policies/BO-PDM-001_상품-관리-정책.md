# 상품 관리 정책

## 목적

BO 관리자가 복지몰 상품을 등록·수정·관리할 때 따라야 할 기준과 절차를 정의한다. 상품 유형 분류, 전시 상태 관리, 등록/수정 프로세스의 일관성을 확보하여 FO 서비스 품질을 보장한다.

---

## 1. 상품 유형 정의

### (1) 상품 정의

- **상품**이란 복지몰에서 임직원에게 판매하는 재화 또는 서비스 단위를 의미한다.
- 모든 상품은 **브랜드** 또는 **판매사**에 귀속되며, 반드시 하나의 상품 유형으로 분류되어야 한다.

### (2) 상품 구분

상품은 수령 방식에 따라 크게 **배송형**과 **티켓형**으로 구분한다.

| 구분 | 설명 |
|------|------|
| **배송형** | 실물 상품을 배송으로 수령하는 유형 |
| **티켓형** | 모바일 티켓/예약권으로 서비스를 이용하는 유형 |

### (3) 상품 유형

상품 유형은 총 4가지로 분류한다.

| 구분 | 상품 유형 | 정의 | 특이사항 |
|------|---------|------|---------|
| 배송형 | **일반 배송 상품** | 배송 받는 실물 상품 | 브랜드 등록 필수, 배송 관련 안내 필수 |
| 배송형 | **배송형 설치 상품** | 설치 기사가 방문하여 설치하는 상품 | 판매사 입점 필수, 배송 관련 안내 필수 |
| 티켓형 | **일반 티켓 상품(e쿠폰)** | 유효기간 내 이용 가능한 모바일 이용권 | 판매사 입점 필수, 모바일 티켓 발급 수단 필수 |
| 티켓형 | **예약 티켓 상품(예약)** | 지정 일시에 시설물을 이용하는 예약 상품 | 판매사 입점 필수, 방문 일시 선택 필수 |

> **참고:** 배송형 상품은 브랜드 등록이 필수이며, 티켓형 상품은 판매사 입점이 필수이다.

## 2. 상품 전시 상태 정의

### (1) 전시 예외 처리 플로우

상품의 FO 전시 여부는 **판매 상태**와 **승인 상태**의 조합으로 결정된다.

```
승인완료 → 판매상태 확인 → [판매중] → FO 전시 O + 주문 O
                        → [판매일시중지] → FO 전시 O + 주문 X
                        → [일시품절] → FO 전시 O + 주문 X
                        → [품절] → FO 전시 O + 주문 X
                        → [판매종료] → FO 전시 X + 주문 X
```

- 승인완료 상태가 아닌 상품은 FO에 전시되지 않는다.
- 판매종료 상품만 FO에서 완전히 비노출된다.
- 일시품절·품절 상품은 FO에 전시되나 주문이 불가하다.

### (2) 판매 상태값

판매 상태는 총 5가지로 관리한다.

| 판매상태 | 내용 | FO 전시 | FO 주문 |
|---------|------|:-------:|:-------:|
| **판매중** | 판매기간 내, 관리자가 설정 (기본값) | O | O |
| **판매일시중지** | 판매기간 내, 관리자가 수동 설정 | O | X |
| **일시품절** | 재고 0 상태가 6일 이내 지속 시 자동 전환 | O | X |
| **품절** | 재고 0 상태가 7일 이상 지속 시 자동 전환 | O | X |
| **판매종료** | 판매기간 종료 또는 관리자가 수동 설정 | X | X |

**상태 전환 규칙:**

- `판매중` → `판매일시중지`: 관리자 수동 전환
- `판매중` → `일시품절`: 재고 0 발생 후 6일 이내 시스템 자동 전환
- `일시품절` → `품절`: 재고 0 상태가 7일 이상 지속 시 시스템 자동 전환
- `판매중` → `판매종료`: 판매기간 만료 시 시스템 자동 전환 또는 관리자 수동 설정
- `판매일시중지` / `일시품절` / `품절` → `판매중`: 관리자 수동 전환 (재고 보충 필요)

## 3. 상품 등록 정의

### (1) PO 직접 등록 플로우

PO 파트너가 직접 상품 정보를 입력하여 등록하는 방식이다.

```
[PO] 상품 정보 입력 → 저장(상품등록중)
  → 승인요청(승인대기)
  → [BO] 승인 심사
    → 승인완료 → FO 전시 (판매상태에 따라)
    → 승인반려 → PO 수정 후 재요청
```

- PO에서 상품 정보를 입력하고 저장하면 **상품등록중** 상태가 된다.
- 승인요청 시 **승인대기** 상태로 전환되며, BO 관리자의 심사를 대기한다.
- BO 관리자가 승인완료하면 판매상태에 따라 FO에 전시된다.

### (2) BO 직접 등록 플로우

BO 관리자가 직접 상품을 등록하는 방식이다. PO를 거치지 않고 BO에서 즉시 상품 정보를 입력한다.

```
[BO] 상품 등록/수정 메뉴 진입 → 상품 정보 입력 → 저장(상품등록중)
  → 승인요청(승인대기)
  → [BO] 승인 심사
    → 승인완료 → FO 전시 (판매상태에 따라)
    → 승인반려 → BO 수정 후 재요청
```

- BO 관리자가 **상품 등록/수정** 메뉴에서 직접 상품을 등록할 수 있다.
- 등록 프로세스(저장 → 승인요청 → 승인심사)는 PO 등록과 동일하다.
- BO에서 등록하더라도 **승인 프로세스는 생략할 수 없다**.
- 등록자와 승인자는 동일 인물이 아닌 것을 권장한다.

### (3) API 연동 등록 플로우

외부 시스템(판매사)에서 API를 통해 상품을 자동 등록하는 방식이다.

```
[외부 시스템] API 상품 데이터 전송
  → [BO] 데이터 수신 및 검증
  → 자동 저장(상품등록중)
  → 승인요청(승인대기)
  → [BO] 승인 심사
    → 승인완료 → FO 전시
    → 승인반려 → 외부 시스템 통보
```

- API 연동 시에도 승인 프로세스는 동일하게 적용된다.
- 데이터 검증 실패 시 등록이 거부되며 외부 시스템에 오류를 반환한다.

### (4) 상품 코드 체계

상품 관리에 사용되는 코드는 2가지이다.

| 코드 | 설명 | 생성 시점 |
|------|------|----------|
| **요청코드** | PO/BO에서 상품 등록 요청 시 발급되는 임시 코드 | 저장(상품등록중) 시 |
| **상품코드** | BO 승인완료 후 부여되는 정식 상품 코드 | 승인완료 시 |

- 요청코드는 등록 과정의 추적·관리 목적으로 사용한다.
- 상품코드는 승인완료 후 FO 전시 및 주문에 사용되는 고유 식별자이다.

### (5) 승인 프로세스

| 단계 | 주체 | 행위 | 결과 상태 |
|------|------|------|----------|
| 1 | PO 파트너 또는 BO 관리자 | 상품 정보 입력 후 저장 | 상품등록중 |
| 2 | PO 파트너 또는 BO 관리자 | 승인요청 | 승인대기 |
| 3 | BO 관리자 | 심사 후 승인 또는 반려 | 승인완료 / 승인반려 |
| 4 | PO 파트너 또는 BO 관리자 | (선택) 승인요청 철회 | 승인철회 |

- 승인대기 상태에서는 PO/BO 모두 상품 정보를 수정할 수 없다.
- 승인반려 시 BO 관리자는 **반려사유를 필수 입력**해야 한다.
- 승인철회 후에는 수정 및 삭제가 가능하다.

### (6) 메뉴 구조

상품 관리 BO 메뉴는 **상품유형별(배송/티켓) 관리**와 **등록/승인 통합 관리** 구조로 구성한다.

```
상품 관리
├── 배송상품 관리
│   └── 배송상품 목록        → BO-PDM-024 (table)
├── 티켓상품 관리
│   └── 티켓상품 목록        → BO-PDM-025 (table)
└── 상품 등록/승인 관리
    ├── 배송상품 승인 목록    → BO-PDM-022 (table)
    ├── 배송상품 등록/수정    → BO-PDM-020 (form)
    ├── 티켓상품 승인 목록    → BO-PDM-023 (table)
    └── 티켓상품 등록/수정    → BO-PDM-021 (form)
```

**PO 메뉴** (변경 없음):

- 상품 관리 > 상품 등록 (신규 상품 입력)
- 상품 관리 > 상품 목록 (등록 상품 조회/수정)

**네비게이션 플로우:**

```
[메뉴: 배송상품 등록/수정] → BO-PDM-020 (등록 모드, 빈 폼)
                              │ 저장 → REGISTERING → 승인요청 → PENDING
                              │
[메뉴: 배송상품 승인 목록] → BO-PDM-022 (승인/반려 처리)
                              │ 승인 → APPROVED
                              │
[메뉴: 배송상품 목록]     → BO-PDM-024 (승인완료 상품 조회)
                              │ 행 클릭
                              ▼
                         BO-PDM-020 (수정 모드, 기존 데이터 로드)
                              │ 저장 → 즉시 FO 반영

(티켓상품도 동일: BO-PDM-021 ↔ BO-PDM-023 ↔ BO-PDM-025)
```

## 4. 상품 수정 정의

### (1) 수정 플로우 (승인완료 후)

승인완료 상태의 상품은 수정 시 별도 재승인 없이 즉시 반영된다.

```
[PO/BO] 승인완료 상품 선택
  → 상품 정보 수정
  → 저장
  → 즉시 FO 반영
```

- 승인완료 상태에서의 수정은 **즉시 FO에 반영**된다.
- 수정 이력은 시스템에 자동 기록된다.

### (2) 등록/수정 폼 모드 제어

BO 등록/수정 폼(BO-PDM-020, BO-PDM-021)은 진입 조건에 따라 모드가 결정된다.

| 조건 | 모드 | 편집 범위 |
|------|------|----------|
| product_id 없음 (메뉴 직접 진입) | 등록 모드 | 모든 필드 입력, 저장 → REGISTERING |
| product_id 있음 + REGISTERING | 수정 모드 | 전체 편집 가능, 승인요청 가능 |
| product_id 있음 + PENDING | 조회 모드 | 읽기전용 |
| product_id 있음 + APPROVED | 수정 모드 | 상품명, 판매상태, 판매기간 편집 → 즉시 FO 반영 |
| product_id 있음 + REJECTED | 수정 모드 | 전체 편집 가능, 재승인요청 가능 |

### (3) API 연동 수정

API 연동 상품의 수정도 직접 수정과 동일한 규칙을 따른다.

```
[외부 시스템] API 수정 데이터 전송
  → [BO] 데이터 수신 및 검증
  → 승인완료 상품 정보 업데이트
  → 즉시 FO 반영
```

- API를 통한 수정 시에도 데이터 검증은 필수이다.
- 검증 실패 시 수정이 거부되며 외부 시스템에 오류를 반환한다.

### (4) 등록/수정 상태값

상품의 등록 및 수정 과정에서 사용되는 승인상태값은 다음과 같다.

| 구분 | 버튼 | 승인상태 | 내용 | 비고 |
|------|------|---------|------|------|
| 등록 | 저장 | **상품등록중** | PO/BO에서 저장 중인 상태 | 수정/삭제 가능 |
| 등록 | 승인요청 | **승인대기** | PO/BO에서 승인 요청한 상태 | 수정 불가 |
| 등록 | 승인철회 | **승인철회** | PO/BO에서 승인요청을 철회한 상태 | 수정/삭제 가능 |
| 등록 | 승인완료 | **승인완료** | BO 관리자가 승인한 상태 | 판매상태에 따라 FO 전시 |
| 등록 | 승인반려 | **승인반려** | BO 관리자가 반려한 상태 | 반려사유 입력 필수 |
| 수정 | 저장 | **승인완료** | 승인완료 상태에서 수정 저장 | 즉시 FO 반영 |

## 5. 승인상태 별 버튼 변경 프로세스 (BO 등록 상품)

### (1) 승인상태 별 버튼 권한

| 상태 | 설명 |

| **비노출** | 버튼 비노출, 클릭 불가 |
| **X** | 해당 승인상태에서 화면 접근 불가 |
