# 티켓상품 화면 테스트케이스

## 테스트 개요

티켓상품 4개 화면(목록→승인목록→등록수정→상세) 간 전체 플로우 E2E 검증.
[BO-PDM-041](../05-wireframes/BO-PDM-041_티켓상품-목록-화면.md)(목록),
[BO-PDM-043](../05-wireframes/BO-PDM-043_티켓상품-승인목록-화면.md)(승인목록),
[BO-PDM-045](../05-wireframes/BO-PDM-045_티켓상품-등록수정-화면.md)(등록수정),
[BO-PDM-047](../05-wireframes/BO-PDM-047_티켓상품-상세-화면.md)(상세) 와이어프레임 기반.

### 범위

- 티켓상품 전용 필드(티켓타입·유효기간·발급방법·패스타입) 검증
- 배송상품 대비 차이점 (브랜드/모델명 없음, 발급정보 탭, 배송비 "무료" 고정)
- 승인완료 후 수정불가 필드 검증
- 화면 간 이동 + 티켓/발급정보 탭 검증

### 전제 조건

- BO 관리자 로그인 (등록+승인 권한)
- 판매사·카테고리 마스터 데이터 준비

---

## 테스트 케이스

### TC-001: 일반티켓 등록 → 승인 전체 E2E

| 항목 | 내용 |
|------|------|
| 구분 | 정상 |
| 사전 조건 | 티켓상품 등록 화면 진입 |
| 테스트 절차 | 1. 상품유형 "일반티켓" 선택 → 2. 7개 탭 필수 필드 입력 (발급정보 탭 포함) → 3. [저장] → 4. [승인요청] → 5. 승인목록(043)에서 [승인] |
| 기대 결과 | REGISTERING → PENDING → APPROVED, 상품코드 발번, 티켓상품 목록(041)에 노출 |
| 우선순위 | 상 |

### TC-002: 예약티켓 등록 — reservation_info 필수 검증

| 항목 | 내용 |
|------|------|
| 구분 | 정상 |
| 사전 조건 | 티켓상품 등록 화면 |
| 테스트 절차 | 1. 상품유형 "예약티켓" 선택 → 2. reservation_info 포함 전체 필드 입력 → 3. [저장] |
| 기대 결과 | 201 Created, REGISTERING 상태 |
| 우선순위 | 상 |

### TC-003: 발급정보 탭 — 발급방법 자동 설정

| 항목 | 내용 |
|------|------|
| 구분 | 정상 |
| 사전 조건 | 등록수정(045) 화면, 기본정보에서 티켓타입 선택 완료 |
| 테스트 절차 | 1. 발급정보 탭 이동 → 2. 발급방법 필드 확인 |
| 기대 결과 | 발급방법이 티켓타입(모바일티켓/바우처)에 연동되어 자동 설정, readonly |
| 우선순위 | 중 |

### TC-004: 발급정보 탭 — 교환/반품 텍스트 입력 (500자)

| 항목 | 내용 |
|------|------|
| 구분 | 정상 |
| 사전 조건 | 등록수정(045) 발급정보 탭 |
| 테스트 절차 | 1. 교환기간 안내 500자 입력 → 2. 반품기간 안내 500자 입력 → 3. 교환/반품 불가 안내 500자 입력 |
| 기대 결과 | 각 필드 500자(1,000 bytes) 정상 저장 |
| 우선순위 | 중 |
